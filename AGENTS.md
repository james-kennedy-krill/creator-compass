# Creator Compass

## Purpose

Creator Compass is an interactive online safety course for a teenage dancer who wants to share dance videos publicly. The parent requires course completion before allowing her to create accounts. Keep the final decision with the parent and respect each platform’s age and feature eligibility rules. The site provides practice, progress tracking, and a family readiness conversation.

## Working in this repo

- Read `README.md` and the relevant parts of `index.html` before making changes. Read `PLAN.md` for open decisions and update it when the owner confirms a change in direction.
- The course is a React 19 + TypeScript app built with Vite and pnpm, using React Router's hash router. Use `pnpm dev` for the local server, `pnpm typecheck` for types, and `pnpm build` (type-check plus build) before committing. The output in `dist/` is a fully static site. GitHub Pages builds and publishes `dist/`, and the root `index.html` is only the Vite entry point.
- Keep learner data on the device. Preserve the no-sign-in, no-analytics, no-tracking, and no-media-upload design. Use fictional examples and test data. Keep names, account handles, locations, schedules, private family terms, and learner backups out of the repo. The GitHub Pages workflow packages the repository root.
- Write directly to the teen in a calm, practical, non-shaming voice. Use realistic dance-related scenarios and give concrete next steps. Encourage trusted-adult support and keep parent facilitation guidance in the Parent Guide where practical.
- When changing platform rules, safety features, or reporting guidance, check current official platform or safety-organization sources. Account for age and regional restrictions where applicable. Update review dates only for material actually checked.

## Editing and verifying

- Curriculum and reference data live in typed modules under `src/data/` (`lessons`, `scenarios`, `platforms`, `resources`, `finalProject`, `parentGuide`), with shapes in `src/data/types.ts`. Gender-aware examples live in `src/data/audience.ts` (scenario variants) and `src/data/spotlights.ts` (lesson Spotlight cards). Variants may change framing and examples but must never drop safety steps, and scenario variants must keep the same number and order of options. Pages are in `src/pages/`, and the shell, navigation, and profile gate are in `src/components/Layout.tsx`. Routes are defined in `src/App.tsx`.
- Course state is managed by a reducer in `src/state/CourseContext.tsx`. Loading, saving, merging, and backups are in `src/state/storage.ts`, and derived progress and readiness live in `src/state/progress.ts`. Profile requirements live in `validateProfile` in `src/state/profileRules.ts`, which both the welcome form and the course gate in `Layout.tsx` use. The dashboard, Resources, and Parent Guide stay open before setup. `readinessItems` is the single source for the Final Project readiness checklist and the parent report. `labSolved` (added after version 1) records scenarios solved at least once, and older saves derive it from `scenarios`. Lesson scores store the answers that were graded in `scores[id].checked` (also added after version 1). Older scores without it treat the current choices as checked. Knowledge checks never reveal a correct answer until the learner picks it. Change state through reducer actions rather than writing to `localStorage` directly.
- Preserve existing progress in `localStorage` under `creator-compass-v1` and compatibility with version 1 JSON backups. The `CourseState` shape in `src/state/types.ts` must stay compatible with the original app. Progress uses lesson IDs, platform names, and positional indices for several activities. Check how existing answers and checkmarks map before reordering items or changing identifiers. Old-style hashes (`#home`, `#lesson-3`) are redirected by `src/legacyHash.ts`, so keep that working when changing routes.
- Render learner-entered and imported text as JSX text, which React escapes. Don't use `dangerouslySetInnerHTML`, and validate any learner-supplied value placed in a URL, as the report does for `mailto:`.
- For curriculum structure or completion changes, check navigation, displayed totals, quiz answer indices, completion conditions, and the Final Project readiness message together. Keep teen-facing instructions aligned with what the UI actually requires.
- Verify affected paths in a browser at phone and desktop widths, including keyboard interaction where relevant. For progress changes, use fictional answers to check saving, reloading, and backup export/import. For agreement changes, check print preview when relevant.
